# WTG–foundation worked example

[Home](README.md) · [WTG guide](WTG.md) · [Foundation guide](FOU.md)

## 1. Illustrative project assumptions

Consider a bottom-fixed wind farm with 60 turbines rated at 15 MW each: 900 MW installed capacity. Assume a 30-year design life and water depths of 30–45 m for this example only. These values are not a turbine recommendation or proof that a foundation concept is suitable.

The developer is comparing two WTG candidates and monopile/jacket concepts. Ground conditions, environmental loads, port limits, and installation capability still require project data. No foundation dimensions or final load values are assumed.

## 2. Follow the engineering decisions

| Step | Action and handoff | Evidence needed to move forward |
|---|---|---|
| 1. Screen turbines | Developer obtains candidate configurations, certification status, energy assumptions, preliminary loads, and service/delivery constraints from each OEM | Comparable assumptions and a list of conditions that could change selection |
| 2. Screen foundations | Foundation designer assesses both concepts using preliminary loads and site/installation data | Concept comparison covering soil response, dynamics, fatigue, fabrication, installation, and uncertainty |
| 3. Select a conditional baseline | Developer selects a preferred turbine and foundation concept, with unresolved conditions assigned | Decision log and closure plan; selection is not a manufacturing release |
| 4. Exchange models | Foundation designer issues the support model; OEM or assigned analysis party checks compatibility | Agreed coordinates, revisions, soil/scour scenarios, damping, and DLC matrix |
| 5. Run and check loads | Analysis party issues integrated loads; both designers verify their scope | Traceable load package and turbine/foundation assessment results |
| 6. Iterate | If a fatigue detail or dynamic response fails, revise the relevant geometry or controls and repeat affected analysis | Impact assessment covering both designs, energy yield where affected, and model/load revisions |
| 7. Freeze and release | Designers confirm convergence; developer coordinates required reviews and approvals | Matched configuration, accepted checks, location coverage, and controlled release documents |

## 3. Example of a condition that reopens design

Suppose FEED uses a preliminary soil model. A later investigation changes the interpreted stiffness at several locations. The foundation designer updates the affected models and checks whether existing location envelopes still apply. The OEM and foundation designer assess whether dynamics and integrated loads need updating before accepting the previous design results.

The decision is based on the agreed sensitivity and change criteria. Do not assume either that every change requires a full rerun or that a small change in one input is automatically harmless.

## 4. Example closure record

| Item | Owner | Closure evidence |
|---|---|---|
| Preliminary soil assumptions | Geotechnical lead and foundation designer | Approved ground model and affected-location assessment |
| Turbine configuration / certification conditions | OEM and developer WTG lead | Configuration record and accepted certification status for the release stage |
| Load-model compatibility | Assigned analysis party and both designers | Interface check and matched revision register |
| Foundation design acceptance | Foundation designer and agreed reviewer | Accepted checks, location mapping, and dispositioned comments |

On a real project, add document references, revisions, due dates, and approvers. Progress follows evidence maturity rather than a fixed number of load iterations.
